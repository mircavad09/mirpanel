# Receipt upload regression — 2026-10-26

## Evidence and cause

Read-only Render logs show `RECEIPT_UNSAFE` with the public message `Fayl zədələnib və ya təhlükəsiz deyil. Başqa fayl seçin.` This is generated by `receipt-file-safety.mjs` before Storage and before browser ownership insertion. The browser-orders release did not change the old safety engine (git diff against ccb0bc0).

A new regression test first failed on a valid decoded JPEG ending in CR/LF, with the same error. The old OCR engine's safety-only path required JPEG EOI / PNG IEND at the absolute end of the buffer. Benign trailing whitespace was incorrectly treated as unsafe. Browser MIME variants (`image/pjpeg`, `image/x-png`) were also rejected before decoding. The customer's original failing file was not available; these are reproduced defects, not a claim to have reproduced that exact file.

## Fix and preserved behavior

- New dedicated `receipt-worker/file-safety.mjs`, used only by `safety-job.mjs`. No OCR, bank matching, content classification, QR or perceptual hashing imports. Existing unrelated OCR work in the working tree is not included.
- Parse actual JPEG/PNG boundaries. Permit benign whitespace/NUL padding after the real end; reject appended executable/archive payloads, including forged second EOI/IEND. Decode pixels under existing 20M-pixel/10k-side limits. Decoder warnings alone are not corruption; fatal errors fail closed.
- Actual signatures and decoder determine stored canonical MIME/extension. Accept normal allowed image/PDF browser hints and aliases, never HTML/ZIP bytes disguised by a filename. Size limit remains 5 MiB, parent/child limits and 25s watchdog remain.
- PDF parser remains isolated, eval disabled; active actions, embedded files, unsafe annotations, excess pages/operations/pixel dimensions and appended payloads remain blocked. Upload is never payment approval.
- Upload stage/code diagnostics are whitelisted; no filename, URL, cookie, key, receipt data or customer data is logged. Storage/network/service errors are not classified as damaged files.
- Browser ownership RPC receives the same bounded write handling as the original submit RPC. Lost-response reconciliation verifies ownership rather than silently bypassing history.
- Success remains `Çek uğurla yükləndi`; no automatic order submission/navigation/WhatsApp. Explicit Continue only. Replacement resets success. Existing retries and double-click protections remain.
- Checkout cache version: `receipt-upload-20261026-1`, applied to home, 22 detail pages and their generator. No product/catalog, Story/banner, payment/reservation, stock or historical data changes. No migration.
